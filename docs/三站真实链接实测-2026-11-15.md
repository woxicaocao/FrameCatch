# 三站真实链接实测

测试日期：2026 年 11 月 15 日（北京时间）。本报告针对用户提供的三条链接，成功以真实媒体文件及其校验为依据；网页元数据可读、作品封面可读或本地回归测试通过，均不等于该网站视频下载成功。

## 新片场：找到并修复程序问题，真实视频下载成功

目标：[新片场 a13856092](https://www.xinpianchang.com/a13856092?from=IndexPick&part=%E7%BC%96%E8%BE%91%E7%B2%BE%E9%80%89&index=7)。

- 普通作品页解析返回 403，是网页访问阶段的限制。
- 用户在辅助窗口已经捕获到该作品的 MP4。原软件在直链分析阶段又返回 403，未创建下载任务。
- 只读检查本软件自己的辅助浏览器缓存，恢复了这条当时仍有效的媒体地址；没有读取 Chrome 的 Cookie 数据库，也没有将签名、用户 IP 或设备标识放入本报告。
- 单变量对照：相同媒体地址、浏览器标识、来源页和软件会话，在系统默认网络、显式直连、显式本机代理三种模式下，均为 **无 Range → 403；Range: bytes=0- → 成功**。
- 官方新片场提取器本身就为 progressive MP4 设置此请求头。原辅助直链与 Chrome 请求导入没有经过该站专用提取器，遗漏了这个要求。[官方提取器源码](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/xinpianchang.py)
- 1.2.1 仅对新片场可信 CDN 域及其子域的 MP4 直链添加完整范围请求，不复制浏览器有限的字节片段范围，不改变其他网站。
- 修复后再次通过真实软件引擎执行“分析 → 入队 → 下载 → 完成 → ffprobe”，全部成功；与手工请求头对照下载得到的文件 SHA256 完全一致。

## Vimeo：原页可读，播放器验证拦截，未完成下载

目标：[Vimeo 1052176560](https://vimeo.com/1052176560)。

- 通过当前可用代理访问普通视频页、官方 oEmbed，均为 HTTP 200。公开元数据确认标题为 **S25 Ultra - Search and Message**，作者 Mackenzie Sheppard，元数据时长 30 秒。
- 普通 yt-dlp 路径停在该 Web API 客户端的登录要求；这不能证明视频本身必须登录。
- 使用公开元数据给出的完整播放器入口，保留公开 hash、真实来源页并比较普通及 Chrome 请求模式，播放器仍返回 HTTP 401。
- 401 正文是 Cloudflare Turnstile 的连接安全验证页；config 接口返回 HTTP 403 和泛化 PrivacyError。不能仅据此归因为会员、密码或账号权限不足。
- 显式直连超时，当前代理能抵达页面但未能通过播放器验证。
- 本轮完成 12 次 HTTP 分阶段检查和 7 次实际提取检查，均未取得可下载清单或媒体地址；**0 个可下载格式，未下载，未做媒体轨道或解码校验**。

证据：`.test-artifacts/real-sites-audit-vimeo-2026-11-15T15-33-21Z/`，包含结构化报告、中文阶段报告及播放器 401 原始正文。

需要由已经能正常播放的 Chrome 提供实际媒体请求，才可继续检验 1.2 的导入下载路径。本次尝试读取现有 Chrome 页面时浏览器连接超时，未接管用户登录态，未自动处理验证，也没有把本地模拟媒体测试算作 Vimeo 实际下载成功。

## 使用结论

新片场本次确认有程序兼容问题并完成真实修复、下载与全片解码；Vimeo 和 Behance 的失败目前发生在取得可下载媒体之前，不能给出“已支持这两条视频下载”的结论。网站验证应由用户在正常浏览器完成，不在软件中自动解决或绕过。

1.2.1 同时修复日志中裸媒体文件名后查询参数的脱敏遗漏，保留 HTTP 错误原因，不在新日志中回显签名、设备信息或用户 IP。旧程序、日志和用户已有文件均保留。
