# 浏览器插件辅助（映取 1.4）

1.4 支持记住本机配对：首次配对后，重新打开映取或 Chrome 会自动恢复连接，不必再次输入配对码。软件需要保持运行；插件不会自行启动未运行的软件。检测网页仍由你主动开启。

适用于正常 Chrome 能播放，但普通解析或内置浏览器无法取得视频的页面。插件从你启用的标签页记录实际媒体请求，把所选视频发送到本机映取；下载、分片合并及音视频组合由便携软件完成。

## 首次加载

1. 完整解压映取便携包，启动 `FrameCatch.exe`，点击工作台的“连接浏览器插件”。
2. 点击“打开插件文件夹”。它是便携目录中的 `浏览器插件` 文件夹，内含 `manifest.json`。
3. 在 Chrome 地址栏输入 `chrome://extensions`，开启右上角“开发者模式”，点击“加载已解压的扩展程序”，选择上述文件夹。可将“映取 · 浏览器助手”固定在工具栏。
4. 回到映取，首次点击“开启插件连接”。在插件弹窗输入显示的 8 位配对码，点击配对。配对码 5 分钟有效。成功后两端记住本机连接，下次打开软件、浏览器或重新加载插件会自动连接。

桌面软件仍然免安装，不注册系统服务、文件关联或本机通信宿主。插件需要在使用的浏览器中首次加载一次；便携目录移动后，浏览器可能需要重新选择新的插件文件夹。固定扩展标识保存在公开的 manifest 公钥中，不包含私钥或用户凭据。

## 检测与下载

1. 在你平常使用的 Chrome 打开目标作品，按网站要求自行登录并完成验证，确认视频能播放。
2. 点击插件，选择“开始检测当前页”。首次会请求网站访问权限：视频经常放在跨域 CDN，因此需要网页及媒体域的访问权限。实际检测由代码限定为你主动启用的标签页。
3. 保持检测开启，刷新作品页并再次播放，记录播放器最初请求的清单。页面跳转或刷新会清除旧资源并继续检测；关闭标签页、点击停止或检测到期会结束该页检测。
4. 在插件中选择与目标视频对应的资源。优先 HLS/DASH 清单或“Vimeo 总清单”（`playlist.json`），也兼容 Vimeo `master.json`。MP4 资源只代表该地址，不保证包含完整音视频；页面中的广告、预览或其他作品也可能出现在候选列表中，需要确认。
5. 点击“发送到映取”。软件会显示分析进度和可选画质，再点击“下载视频”。发送不等于立即下载。

独立 `.ts`、`.m4s`、初始化文件、纯音频不会列为完整视频。清单可以由下载引擎解析、选择画质并合并音视频；单条 MP4 只能提供该文件自身包含的画质和轨道。不要把只有视频轨道的资源当作包含完整声音的成品，优先选择播放器的总清单。

## 更新已有插件

1. 关闭旧版映取，启动新的 1.4 便携版。两版均保留自己的数据。
2. 浏览器扩展仍指向你首次加载的文件夹。将新版 `浏览器插件` 文件夹内的文件复制覆盖到原插件目录，然后在 `chrome://extensions` 点击该插件的“重新加载”按钮。也可以加载新版文件夹；若浏览器报告相同扩展标识冲突，采用前一种方法，无需删除旧插件。
3. 确认插件详情中的版本为 1.4.0。首次升级到记住配对功能时再配对一次，以后无需重复。开启当前页检测后刷新作品，从开头播放；局部 MP4 会过滤，并显示重新捕获总清单的说明。
4. 选择“Vimeo 总清单”或 HLS/DASH，发送到新版软件，再选择画质下载。不要直接重试原来的 `range` 片段任务。

Vimeo 可能将 MP4 的某个字节区间放在 `/v2/range/prot/…` 路径和 `range` 参数中；这些地址的签名也与范围绑定。1.3.1 不会删除参数或修改签名猜测完整地址。新版从真实 `playlist.json` 读取初始化和全部分片；清单若缺少初始化或轨道不完整，会明确失败并保留文件。

## 登录态与隐私

- 不读取密码，不扫描 Chrome 的账号数据库，不遍历所有网站的 Cookie。
- 只记录启用标签页的请求；发送时仅附所选媒体实际请求携带的 Cookie、浏览器标识及来源信息。不收集 Authorization、POST 请求正文或登录 API。
- 插件仅将随机本机配对令牌存入受信任的 `storage.local`，不写同步存储。网站 Cookie、带签名视频地址和候选资源仍只在受信任的会话存储中；停止或清空检测会清除该页候选，浏览器会话结束后重新检测。
- 软件在 `data/extension-pairing.json` 保存令牌的 SHA256 校验值和自动连接设置，不保存令牌原文或网站登录数据。请保管好便携目录及浏览器资料。移动同一便携目录可保留连接；全新目录、更换浏览器配置或电脑需要首次配对。
- 映取只监听本机 `127.0.0.1:46783`，验证固定扩展来源、Host 和配对令牌；普通网页和局域网设备不能通过该入口直接创建任务。退出软件保留配对，下次启动自动恢复；“暂停自动连接”保留配对但停止连接；“忘记配对”撤销旧令牌并关闭连接。
- 接收的媒体 Cookie 转为精确媒体域的本机 Cookie 文件，保存在软件旁 `data/captures`，供重试使用。已生成的文件不会自动删除。不要分享含登录态的整个便携目录。
- 插件窗口与本机接口不回显 Cookie、媒体签名或本机 Cookie 文件路径。软件仍须把媒体请求发送给原网站及其 CDN，以执行下载。

## 排障

| 提示或现象 | 处理 |
| --- | --- |
| 找不到插件 | 确认选择的是含 `manifest.json` 的 `浏览器插件` 文件夹；需要 Chrome 120 或更新版本。 |
| 无法开启连接 | 端口可能被另一个映取窗口占用。关闭那个窗口中的插件连接，再在当前版本开启。 |
| 等待映取启动 | 打开已配对的同一便携目录中的软件，插件会自动重试；无需再次输入配对码。 |
| 配对失效 | 忘记配对、清除扩展资料、更换软件数据目录或重新配对后，使用当前配对码再连接一次。正常重启无需重配。 |
| 没检测到资源 | 先启用检测，再刷新并播放。确认已授权网页及跨域 CDN。缓存、播放器实现或保护机制可能使媒体不可识别。 |
| 插件已发送，但分析失败 | 查看映取中的具体原因；保持软件和浏览器使用相同的代理/网络，重新播放、清空旧候选并发送新的清单。 |
| 映取仍要求验证 | 复制请求信息不等于完整复用浏览器环境。网站可能仍拒绝下载客户端；插件不保证解决 Cloudflare、地区或账号权限限制。 |
| 作品不存在 | 先在原网页确认。插件可改善未带登录态导致的误判，无法恢复确已删除、私密或无权限的作品。 |

插件不自动完成网站验证，不提供 DRM 解密。Vimeo、Behance 等站点是否能下载，以实际取得媒体和完整成品校验为准，不以看到标题、封面或检测到资源为成功依据。

技术依据：[Chrome 请求监听](https://developer.chrome.com/docs/extensions/reference/api/webRequest)、[可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)、[会话存储](https://developer.chrome.com/docs/extensions/reference/api/storage)、[本地加载扩展](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。
