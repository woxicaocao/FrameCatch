# 映取 FrameCatch 使用说明

映取是 Windows 便携视频下载器。适用于 Windows 10 22H2 / Windows 11 的 x64 电脑。

## 启动

1. 将便携 ZIP **完整解压**到有写入权限的目录，例如 `D:\工具\映取`。
2. 双击 `FrameCatch.exe`。不要直接在压缩软件内运行，也不要只复制一个 EXE。
3. 所需的下载、合并和运行组件已随包提供，不需要安装 Python、Node、FFmpeg，也不需要管理员权限。

软件运行时，配置、下载记录、日志和中间文件保存在软件旁的 `data` 目录。完整视频默认保存在旁边的 `Downloads`，可在设置中修改。

## 下载视频

抖音分享口令和视频号短链请使用左侧“抖音 / 视频号”。整段分享文案可直接粘贴，识别来源后点击“分析分享内容”，成功后核对作品、选择画质并下载。视频号原网页若只提供微信二维码预览，当前不能从该页下载视频；软件会明确提示。详见同目录《抖音与视频号》。

1. 在工作台粘贴视频网页的网址，软件会自动分析，也可以点击分析按钮。
2. 检查视频标题和画质。默认选择可获取的最高画质，也可以降低分辨率。
3. 如果网址中包含多个视频，先勾选要下载的项目；不会默认下载整个播放列表。
4. 点击下载。任务按队列顺序运行，界面显示下载、合并、校验等状态。
5. 完成后点击打开文件夹查看成品。

同一视频的 HLS/DASH 传输分片会自动合并；分离的视频和音轨也会合成完整文件。B 站多 P 和播放列表中的独立视频分别保存，不会拼成一条影片。

软件优先保留原始画质，合并过程不重新编码。兼容时输出 MP4，其他编码组合输出 MKV。MKV 也包含完整画面和声音；个别剪辑软件或系统播放器可能需要支持相应编码。

## Chrome 插件辅助（1.3 新增）

请使用 1.3.1 及配套同版本插件。该版修复 Vimeo/Behance 的局部 MP4 被当作完整资源的问题，支持“Vimeo 总清单” `playlist.json`。已加载旧插件的用户，需要把新版插件文件复制覆盖到原扩展目录，再到 Chrome 扩展管理页点击“重新加载”；仅启动新软件不会更新浏览器中已经加载的插件。详细步骤见《浏览器插件辅助》。

普通 Chrome 可以正常播放时，点击工作台“连接浏览器插件”，按提示加载便携目录内的 `浏览器插件`，输入本次配对码。然后在 Chrome 插件中“开始检测当前页”，刷新并播放视频，选择完整清单或 MP4，点击“发送到映取”。软件分析后仍需选择画质并点击下载。

插件沿用实际媒体请求的相关会话信息，不读取密码或扫描浏览器账号数据库。桌面软件保持免安装；插件需要在浏览器首次加载。1.4 起首次配对后会记住本机连接，软件、浏览器重启后自动重连；网站请求仍只在会话内保存。详细步骤、权限说明和排障见同目录《浏览器插件辅助》。

## 浏览器辅助分析（1.1 新增）

1.2.1 已修复新片场 MP4 直链的必要请求头遗漏。如果此前“检测到视频，但分析或下载 403”，请使用 1.2.1 并重新取得当前有效的媒体链接；旧的签名地址可能过期。网页本身若仍返回 403，需先通过可播放的浏览器取得视频资源。

如果内置窗口出现 Cloudflare 验证失败，而正常 Chrome 可以播放，请改用 1.2 的“导入 Chrome 视频请求”。具体步骤见同目录《Chrome接力下载》。这条路径不需要安装浏览器扩展。

适用于普通解析提示 401、403、登录或验证，但你能在正常浏览器播放的视频：

1. 在主窗口粘贴作品页或视频页网址，点击“浏览器辅助分析”。
2. 在新窗口下方播放目标视频。如果网站要求登录、密码或验证，请自行完成；此窗口不共享 Chrome 的登录状态。
3. 上方出现媒体资源后，优先选择对应视频的 DASH/HLS 清单，或完整 MP4，再点击“分析所选资源”。页面中其他视频也可能成为候选，需确认对应关系。
4. 返回主窗口选择画质并下载。软件会使用捕获时的来源页面、浏览器标识、相关站点 Cookie 和代理；单个 ts/m4s 分片不会列作完整视频。

辅助浏览器会话在 `data/helper-browser`，每次选择资源产生的域限定 Cookie 文件在 `data/captures`。这些数据仅由本机使用，不会上传至应用服务器，也不会自动读取 Chrome 的登录资料。请勿分享这两处数据或带登录态的便携文件夹。清理下载临时文件不会删除登录态。

本功能不保证所有站点可用：网站可能限制嵌入浏览器或下载客户端；媒体地址可能过期、受 DRM 保护，或者只暴露无法独立下载的片段。若捕获后重试仍失败，可重新播放并捕获新资源；若辅助窗口本身也无法播放，应先解决其网络或网站访问问题。带账号密码的手动代理暂不支持辅助窗口，可改用自己的本机代理端口。

仅当你点击辅助入口时才会打开窗口；普通粘贴仍使用原解析流程。

## 下载记录与恢复

- 正在运行的任务可以取消；取消会停止该任务的下载和合并子进程。
- 失败、取消或上次退出时未完成的任务可以重试。来源支持时会利用已下载的数据续传；服务器变更或不支持续传时可能重新下载。
- 软件异常退出后，不会把半成品标记为完成；重新启动后可在记录中重试。
- 任务只有在下载、合并成功，并检查应有的媒体轨道后，才显示完成。
- 同名文件自动区分，不覆盖已有视频。

中间分片和原始音视频轨道默认保留，输出目录内的 `.framecatch-staging` 也可能保留临时副本或硬链接，可能占用比最终成品更多的空间。已完成任务可使用清理功能，软件会先展示目录、数量、逻辑大小和删除原因，**经你明确确认后**才删除这些中间文件；完整视频、日志及任务记录保留。逻辑大小不一定等于实际释放的磁盘空间。

## 登录与 Cookie

公开内容通常无需 Cookie。部分高画质、年龄限制、私密或账号可访问的内容需要登录态。

在设置中导入 Netscape 格式的 `cookies.txt`，保存后重新分析或重试。JSON 格式的浏览器 Cookie 导出不能直接作为此格式使用。Cookie 失效时，需要重新导出并选择新文件。

Cookie 文件相当于登录凭据，请妥善保管。软件不要求输入账号密码；不要把该文件连同便携包分享。软件记录 Cookie 文件路径，不会主动把 Cookie 上传到其他服务。视频平台仍会在相应媒体请求中接收它需要的 Cookie。

## 网络与代理

电脑本身需要能访问目标网站。如果当前网络不能直接访问，可在设置中填写你已有的代理，例如：

- HTTP 代理：`http://127.0.0.1:7897`
- SOCKS5 代理：`socks5://127.0.0.1:1080`

地址和端口应使用你自己的实际配置。保存设置后再分析或重试。软件不提供代理服务。

## 支持范围与常见问题

- B 站、YouTube、Vimeo、新片场使用 yt-dlp 的平台解析器，具体视频能否下载仍取决于网站当前接口、权限和网络。
- Behance 以及其他网站使用通用网页、嵌入视频或媒体链接解析；不是所有作品页都能识别。
- 需要交互式验证码、内置浏览器才能发现的动态媒体，首版可能无法处理。
- DRM 保护或无访问权限的内容无法通过本工具下载。
- 分析失败或 HTTP 403：检查网址、网络和 Cookie；站点接口也可能已改变。
- HTTP 429：目标站点暂时限制请求，可稍后重试。
- 分片缺失：任务会报错，不会跳过缺片后把视频标为成功。
- 磁盘不足：工作目录和成品目录都需要足够空间。保留分片时请预留额外容量。
- 依赖缺失：保持便携目录结构完整；重新解压到新目录，或按《依赖更新说明》恢复相应组件。
- 无法启动：确认是 x64 Windows 10 22H2 / Windows 11，且完整解压到了可写目录。

任务失败时可打开日志查看详细原因。发送日志前请自行检查其中是否含有不希望分享的视频标题或网址。

当前各平台的真实联调结果和已知限制见同目录《验收记录》。

## 迁移便携目录

先退出软件，再复制整个软件目录。配置和历史记录会随 `data` 一起保留，软件内部的保存路径会随便携目录迁移。若你使用外部保存目录、外部 Cookie 文件或换了电脑，请在设置中确认这些位置仍然有效。

软件不需要 AI API 密钥，日常下载、分析和合并不会产生模型 token 消耗。

相关组件的版本、下载来源和 SHA256 记录见 `resources/dependencies.json`；开源许可和 FFmpeg 源码见 `resources/licenses`。
