# 依赖更新说明

视频平台会更新接口。某个站点突然无法解析时，更新 yt-dlp 往往比重新安装整个软件更合适。首版提供依赖版本显示和手动更新说明，不在后台自动替换组件。

## 用户手动更新

1. 退出映取，确认没有下载或合并进程仍在运行。
2. 复制整个便携目录留作备份，保留原有 `data`、视频文件和组件。
3. 从下列官方发布页获取 **Windows x64** 对应文件，按官方 SHA256 校验下载内容。
4. 将新文件放到便携目录的 `resources/bin`。若系统提示替换，确认来源和备份后再操作。
5. 重新打开映取，在设置中检查版本，先用一个公开短视频验证解析、下载和合并。

| 组件 | 官方来源 | 更新时的注意事项 |
| --- | --- | --- |
| yt-dlp | <https://github.com/yt-dlp/yt-dlp/releases> | 选择独立运行的 `yt-dlp.exe`；`SHA2-256SUMS` 提供校验值。官方 x64 EXE 已携带 EJS 脚本。 |
| Deno | <https://github.com/denoland/deno/releases> | 选择 `deno-x86_64-pc-windows-msvc.zip`，解压得到 `deno.exe`；对应 `.sha256sum` 提供校验值。不要下载 denort 或 ARM64。 |
| FFmpeg / ffprobe | <https://github.com/FFmpeg-Builds/FFmpeg-Builds/releases> | 本包使用 LGPL shared 的 Windows x64 构建。`ffmpeg.exe`、`ffprobe.exe` 和该构建的所有 DLL 必须成套更新，不能混用不同版本。校验见 `checksums.sha256`。 |

`resources/dependencies.json` 记录的是出厂时验证的组件版本。用户手动更换后，设置中运行检测得到的版本反映实际组件；JSON 文件不会假装已自动更新。

手动更新时一并保留新组件对应的许可证与来源信息。FFmpeg 的 LGPL/GPL 取决于具体构建，不能仅凭程序名称判断。本包使用的构建由 `ffmpeg -L` 明确报告为 LGPL-3.0-or-later。

## 开发者重新准备依赖

项目内的 `scripts/prepare-deps.mjs` 固定了已验证的组件版本、发布资产及校验文件名称。首次构建可运行：

```powershell
npm run deps:prepare
```

脚本从官方 GitHub 仓库获取版本数据，使用上游校验文件和发布资产 SHA256 进行比对。下载包和解压缓存保存在 `.resources-cache`，不进入便携发布包。已有组件与清单 SHA256 匹配时会跳过下载并检查可执行版本。

如需更新组件，先在脚本中修改固定版本及对应源码提交，复核官方资产名称，再运行：

```powershell
npm run deps:prepare -- --refresh
```

如果目标文件内容改变，脚本先保留带时间戳的备份，再覆盖目标；不会删除旧文件、下载缓存或解压缓存。备份文件不应作为新的发布组件。打包时应使用准备脚本产生的清单确认当前文件。

脚本会读取当前进程代理，或 Windows 已启用的 HTTP 代理，仅用于该准备进程；不会修改系统代理配置。也可以在命令对应的终端内配置 `HTTPS_PROXY`。该脚本使用 Node 24 的 `--use-env-proxy` 能力，开发环境请使用 Node 24 LTS 或更新的兼容版本。

每次发布前应运行类型检查、自动化测试、真实媒体合并验证和便携包启动检查。依赖更新不等于保证每个网站的每个视频都可下载。
