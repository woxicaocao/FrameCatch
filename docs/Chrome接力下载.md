# 从 Chrome 导入视频请求（1.2）

当普通 Chrome 可以正常播放，而映取普通解析或内置浏览器提示 401、403、Cloudflare 验证失败时，可用这一免扩展方式。它使用你在 Chrome 中已经正常发出的媒体请求，不会自动完成网站验证，也不提供 DRM 解密。

## 在 Chrome 中复制一条媒体请求

1. 在 Chrome 打开视频页，确认能正常播放。需要网站验证时自行完成。
2. 按 F12，切到“网络 / Network”。保持网络记录开启，刷新网页后再次播放视频，以记录最初的视频清单。
3. 在过滤框先输入 `m3u8`；没有结果时分别尝试 `mpd`、`master.json`、`mp4`。优先选完整的 HLS/DASH 清单；Vimeo 可能使用 `master.json`。
4. 对应请求应是正常播放时成功返回的请求。选中一条，右键“复制 / Copy”→“复制为 cURL / Copy as cURL”。如有 bash/cmd 两种，优先选 bash。
5. 返回映取 1.2，点击“导入 Chrome 视频请求”，再点“从剪贴板分析”；也可在对话框粘贴区按 Ctrl+V，然后点击分析。
6. 分析成功后选择画质并下载。

Chrome 的“复制为 cURL”会把一条请求及相关请求头复制为文本。映取只解析该文本，不会执行 cURL 或其他命令。参考：[Chrome 官方网络面板说明](https://developer.chrome.com/docs/devtools/network/reference#copy-a-request-a-filtered-set-of-requests-or-all-of-them-to-the-clipboard)。

## 选择完整资源

- 首选 `master.m3u8`、`playlist.m3u8`、`.mpd` 或 Vimeo CDN 的 `master.json`，通常可保留画质与音视频选择。
- 也可选择完整的 MP4；清晰度取决于你复制的那条 MP4。
- `.ts`、`.m4s`、`init.mp4`、带编号的 chunk/segment/fragment 只是传输片段，不能作为完整视频导入。
- 选择“复制为 cURL”单条请求；“复制所有请求”“复制响应”“复制为 fetch”或“复制为 PowerShell”不是本入口接受的格式。
- 不应选择登录、账号、付费或其他 POST API。该入口仅接收媒体 GET/HEAD 请求。

## 隐私与安全

请求可能包含登录 Cookie 或有时效的媒体签名。请只粘贴到自己的本机映取，不要发到聊天、论坛或第三方网站。

- 不安装浏览器扩展，不扫描 Chrome 的账号或 Cookie 数据库。
- 不后台读取剪贴板；只有你点击对应按钮时才读取。
- 原始 cURL 不写入任务记录或日志，界面只显示收到的内容摘要。
- 相关 Cookie 转为仅适用于媒体 URL 域名的本地文件，放入 `data/captures`，不会转成跨站通用 Cookie 请求头。
- 代理采用导入时的软件设置，请保持与 Chrome 相同的网络出口。媒体地址过期时重新播放并复制。
- 带 Cookie 的本机捕获文件与会话数据需要妥善保管，勿分享带登录态的整个便携目录。

## 仍然失败时

- 没有找到清单：先打开 Network，再刷新并播放；只打开面板而没有重新播放，可能错过最初的请求。
- 提示缺少浏览器标识或来源页面：重新在实际媒体请求上复制为 cURL；只复制网址不能保留这些信息。
- 请求带 POST、Authorization 或外部文件参数：请检查是否选错了账号/API 请求；当前入口不会导入这些内容。
- 导入后仍是 401/403：请求可能已经过期、出口不同，或媒体服务器仍要求原浏览器环境。此方法不能保证所有站点可用。
- 受 DRM 保护或只有无法独立使用的媒体片段：当前软件不能下载成完整视频；不要把验证失败等同于必须购买会员。

本功能的本地受限媒体测试结果见《验收记录》。实际网站仍以你自己的播放与下载结果为准。
