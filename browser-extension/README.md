1.5 配合桌面新增的“抖音 / 视频号”标签页使用；自动配对连接方式沿用 1.4。插件只能捕获当前网页真实播放的媒体，视频号仅二维码预览的页面不会产生可下载视频。

1.4 支持首次配对后自动连接。软件或 Chrome 重启、插件重新加载后，打开映取即可自动恢复，不必再输入配对码。软件未启动时插件显示等待，不会自行启动软件；检测当前网页仍由你主动开启。首次升级此功能需要再配对一次。

1.3.1 新增“Vimeo 总清单” `playlist.json`，并过滤带签名字节区间的局部 MP4。已加载旧插件时，将本目录文件复制覆盖到原插件目录，再在 Chrome 扩展管理页点击“重新加载”；启动映取 1.3.1 后重新配对、刷新作品页并从开头播放。仅重启软件不会更新浏览器里的插件。

## 首次加载

1. 在 Chrome 地址栏输入 `chrome://extensions`，开启右上角“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本说明所在的文件夹（便携包内名为 `浏览器插件`，源码内名为 `browser-extension`）。不能只选择 ZIP。
3. 将“映取 · 浏览器助手”固定到浏览器工具栏。首次加载后请不要移动扩展文件夹；移动后可重新加载。
4. 首次启动映取便携版，点击“连接浏览器插件”→“开启插件连接”。把软件显示的 8 位配对码输入插件并点击“配对”。配对码有时效；成功后会记住本机连接，正常重启无需重配。

## 下载操作

1. 在平常使用的 Chrome 中打开作品，确认账号已登录且视频可以播放。
2. 点击插件 →“开始检测当前页”。首次需授权 HTTP/HTTPS 网站访问，以覆盖作品页及不同域名的视频 CDN。代码只记录用户手动启用的标签页。
3. 开启检测后刷新页面，再播放视频。插件不会补读开启前的历史网络请求。
4. 从检测列表选择完整 HLS/DASH 清单或 MP4，点击“发送到映取”。清单优先列出；`.ts`、`.m4s`、初始化文件和明显的传输分片不会列入。
5. 返回映取查看分析结果，选择画质并下载。分片和音视频合并由桌面软件完成，插件不自动创建下载任务。

遇到签名过期、401 或 403 时，请确认 Chrome 仍能播放、软件与 Chrome 使用相同网络出口，再重新播放捕获。插件沿用实际媒体请求的信息，不能保证服务器接受另一个客户端；真实删除、账号无权限、地区限制或 DRM 保护不因插件而消失。插件不会自动完成网站验证。

## 数据与权限

- 不读取密码、Chrome Cookie 数据库或其他浏览器资料，不调用调试接口。
- 不扫描全部 Cookie，仅保留所选标签页里实际视频请求携带的相关 Cookie、Referer、Origin 和浏览器标识。无需单独导出 Cookie 文件。
- 请求信息只放在扩展的可信会话存储，普通网页不能访问，正常浏览器重启后消失。仅随机本机配对令牌存入受信任的扩展本地存储，不写同步存储，不持久保存网站 Cookie 或媒体地址。软件在自己的 data 目录仅保存配对校验值。
- 检测最长 30 分钟，最多保留 30 条资源。停止检测、清空资源、页面导航或关闭标签页会清除相应捕获内容。
- 只把用户选择的一条媒体请求发送到 `127.0.0.1:46783`，本机连接需要配对。媒体签名和 Cookie 不显示在列表中，也不发送到第三方服务。
- 映取为完成下载可能在自身便携目录 `data/captures` 保存仅对应媒体域的 Cookie 文件；请勿分享带登录态的整个便携目录。
- 扩展访问权限可在浏览器扩展管理页撤回。停止检测会清空捕获；桌面“暂停自动连接”保留配对并暂停监听，“忘记配对”撤销原令牌。插件“忘记本机连接”清空插件本机凭据；要撤销桌面授权请同时在软件中忘记配对。

## 测试

开发环境可执行 `node --test tests/browser-extension.test.mjs`。这些测试使用模拟 Chrome API、内存请求及虚构凭据，不访问用户真实登录资料。端到端测试与实际网站测试由桌面项目单独记录；本地测试通过不等于 Vimeo、Behance 已真实下载成功。
